# Community Engagement

This area captures how UX AI community engagement can connect to durable context without turning the repository into a social platform.

## Use the right surface for the right job

Use Teams, Viva Engage, email, demos, office hours, and conversations for:

- reach
- discussion
- questions
- sharing emerging work
- finding collaborators
- creating energy

Use `uxai-context` when something should remain useful after the conversation.

Examples include:

- project context
- a meaningful decision
- research or evidence
- prototype learning
- a reusable pattern
- a skill or workflow
- an agent recipe
- a useful internal tooling reference
- a pointer to an authoritative standard

## The loop

```text
community signal
      ↓
conversation / demo / question
      ↓
try / build / research / learn
      ↓
capture durable context
      ↓
share useful learning back
```

The goal is not to archive every conversation.

The goal is to make sure useful work does not disappear simply because the conversation moved on.

## Participation

People should be able to participate at different levels:

```text
browse → understand → discuss → contribute → reuse/share
```

Contribution should not require Git expertise.

GitHub.com is sufficient for lightweight participation; GitHub Desktop + VS Code + Copilot can support regular contributors.

## Not yet

Detailed channel strategy, cadence, moderation, broadcasts, and community programming should be treated as a separate exercise when the UX AI community is formally launched.

This README preserves the relationship between those engagement surfaces and the context system.
