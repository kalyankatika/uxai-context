# Community Contributions

Community participation should be permissive. Promotion into durable or shared context should be selective.

> **Share broadly. Promote selectively.**

Not every prototype, prompt, demo, or vibe-coded experiment needs to become canonical context.

The bar is not polish. The bar is whether the work adds durable understanding or reusable capability.

## Showcase vs contribution

### Showcase

Worth seeing, discussing, or learning from.

Examples:

- an interesting prototype
- a model experiment
- a clever interaction
- a new prompt
- a demo
- an emerging idea

A showcase can remain conversational.

### Contribution

Worth preserving because it adds something to the larger context.

A strong contribution usually has some combination of:

- a real problem, question, or hypothesis
- an artifact or evidence
- meaningful learning
- implications for the work
- enough context for someone else to understand or continue it
- value beyond the individual experiment

## Lightweight contribution questions

Before promoting something into durable context, ask:

1. **What problem, question, or hypothesis are we addressing?**
2. **What did we actually try?**
3. **What did we learn?**
4. **What evidence or artifact supports that learning?**
5. **Why might this matter beyond this one experiment?**
6. **Can someone else understand or continue it?**

These are prompts for judgment, not a numerical scoring rubric.

## A simple lifecycle

```text
EXPLORE
community conversation / experiment
        ↓
INCUBATE
hypothesis + artifact + learning + owner
        ↓
PROMOTE
durable project context or reusable shared asset
```

### Explore

Open participation. No governance burden.

### Incubate

The work has enough substance to deserve continued attention. Keep it close to the project where it is being tested.

### Promote

The work has become durable enough to inform future projects or be reused.

Promotion might result in:

- a decision
- a research finding
- a prototype learning
- a pattern
- a skill
- an agent recipe
- a tooling reference
- a pointer to a standard

## Guiding principle

> **Promote signal, not activity.**

A small experiment with a strong hypothesis and meaningful learning can be more valuable than a polished demo with no reusable insight.
