# Discovery working session

> **Reference example only — not an actual project record.**

## Context

Review the latest discovery prototype and decide what needs to be learned before expanding the concept.

## Discussion

The prototype made related work easier to find, but the team noticed that some relationship labels were too technical.

Research also raised a question about whether people want to start from a project, a capability, or a person.

## Decisions

- Keep the relationship model in the next prototype.
- Simplify the labels before the next evaluation.
- Test multiple starting points rather than assuming project-first navigation.

## Open questions

- Which relationship types are genuinely useful to users?
- Should all relationship types be visible by default?
- What is the simplest useful starting view?
